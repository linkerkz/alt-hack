# 005 — Живой пульт станции

Статус: done

## Цель

Пульт станции листал сценарий по `?step=N`: кнопки ролей только меняли URL.
Нужно, чтобы кнопки ДСЦС и ДСП меняли ход инцидента в базе, экраны всех
участников видели изменения друг друга, а наряд по QR влиял на пульт.

## Направление

- Ход инцидента — в Supabase: статус, выбранный вариант, согласование ДНЦ,
  принятые ДСП поезда; наряд привязан к инциденту. Шаг пульта выводится из
  них, в URL остаётся только вид экрана (вкладка, фокус, панель, диалог,
  просматриваемый вариант).
- Действия — Server Actions пульта: проверяют роль и станцию, затем — что
  шаг ещё актуален (другой экран мог успеть раньше). Пишет сервер секретным
  ключом, политик записи нет.
- Каждое действие пишет в хронологию станции (время симуляции); ход работ
  берётся из наряда — рабочий отмечает чеклист по QR.
- Наряд связан с инцидентом внешним ключом (каскад при сбросе). Рабочий
  явно берёт наряд в работу — до этого чеклист закрыт. Этапы наряда (взят,
  выполнен) двигают инцидент и пишутся в хронологию триггером в базе: рабочий
  работает по QR, а не с пульта.
- Экран перечитывает базу раз в 3 с, пока вкладка видима.
- Демо-пульт играет участников без экрана: датчик, ДНЦ, служба; «Далее»
  делает следующий шаг за того, чья очередь; «Сброс» чистит инциденты станции.

## Вне рамок

Supabase Realtime (хватает опроса), пульты остальных ролей, живое время
поездов (план путей и показатели — по шагу сценария), уведомления.
