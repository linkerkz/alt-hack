# 006 — Штатный приём поездов

Статус: todo

## Цель

Сейчас пульт ДСП оживает только при сбое, а в штатном режиме показывает
«Новых задач нет». Нужен ежедневный сценарий: ДСП видит поезда «К нам»
на горизонте 3 часов и по каждому решает — **принять поезд на путь по плану**
или **выбрать другой путь**. Система проверяет выбор и показывает последствия.
Так видно, что система полезна каждую смену, а сбой — частный случай той же
механики.

## Направление

- **Источник поездов — база.** Очередь приёма строим из `track_plan`,
  `routes` и `tracks` (засеяны в `supabase/seed.sql`): поезда «К нам», которые
  прибудут в пределах горизонта от часов пульта. Проездом и уже прибывшие
  в очередь не попадают.
- **Решение ДСП хранится в базе.** Принятый путь, маршрут, время и кто принял —
  новой таблицей приёмов (на станцию и поезд одна запись). Решение
  принимается вне инцидента, поэтому колонка `incidents.route_tasks` для него
  не годится. RLS включён, пишет сервер, как в плане 005.
- **Новая команда пульта** в `features/station-console/commands.ts` и
  `actions.ts`, рядом с существующей `route`. Роль — ДСП. Перед записью сервер
  проверяет, что решения по поезду ещё нет: его мог принять другой экран.
  Решение пишется в хронологию (`timeline_events`, без инцидента).
- **Выбор другого пути: проверки.** Для каждого пути станции система
  показывает, можно ли на него принять поезд, а если нельзя — почему.
  Путь недоступен, если:
  - нет маршрута из горловины, откуда идёт поезд, или в маршруте
    неисправная стрелка (открытый инцидент);
  - пассажирскому поезду нужен путь с платформой; тупик — только для манёвров.
  Недоступные пути видны, но выбрать их нельзя.
- **Конфликт, а не запрет.** Путь занят на окне прибытие–отправление (по
  `track_plan` с учётом уже принятых решений) — выбрать его можно, но
  система показывает конфликт: какой поезд мешает и на сколько минут
  сдвинется он или принимаемый поезд.
- **Последствия выбора.** Окно занятия нового пути, конфликты, которые
  появятся, и изменение загрузки путей. Отдельный пересчёт индекса
  эффективности в эту задачу не входит.
- **Уведомление машиниста.** Если путь отличается от плана, в хронологии
  появляется «машинист уведомлён: новый путь N» (без отдельного канала, как
  в сценарии сбоя).
- **UI — панель ДСП.** Штатные задачи приёма идут в общий список
  (`dsp.ts` → `TaskList` / `DspTaskCard`) вместе с задачами сбоя, по
  времени прибытия. Выбор другого пути — раскрытие карточки или диалог по
  образцу `ReturnToServiceDialog` (состояние в URL, как `confirm`). Собираем
  из `components/ui/`, разовых стилей нет.
- **План занятости путей** (`plan.ts`) в штатном режиме показывает поезда
  на принятом пути: по плану — как сейчас, по другому пути — нитка «новый».
  Пока решения нет — нитка плана.
- **Сбой поверх штатного приёма.** Приём относится ко всем прибывающим, в том
  числе к 101 и 2001. Когда сбой затрагивает поезд, его штатная задача уходит
  из списка, а решение (если было) помечается в хронологии как пересмотренное
  из-за инцидента. Дальше действуют задачи сбоя. Сценарий сбоя остаётся
  прежним.
- **«Сброс» на демо-пульте** чистит и решения о приёме станции.
- **Словарь** (`docs/core.md`): «Приём поезда» расширяем — это задача ДСП
  принять поезд на путь, по плану или по новому плану при сбое. Новых синонимов
  («отклонить», «перенаправить») не вводим: действие называется «выбрать другой
  путь».

## Вне рамок

Отправление поездов (задержку согласует ДНЦ — отдельный план 007),
пересчёт индекса эффективности и вариантов сбоя от штатных решений, живое
время (часы пульта по-прежнему идут по шагу сценария), реальный канал
уведомления машиниста, приём на пути соседних станций.

## Критерии приёмки

- [ ] В штатном режиме у ДСП есть задачи «Принять N на путь M в ЧЧ:ММ» по всем поездам «К нам» на горизонте
- [ ] «Принять по плану» записывает решение в базу и хронологию; задача становится выполненной на всех открытых экранах
- [ ] «Другой путь» показывает все пути станции: доступные — с последствиями, занятые — с конфликтом, недоступные — с причиной (нет маршрута, стрелка неисправна, нет платформы, тупик)
- [ ] Выбор другого пути меняет план занятости путей и пишет в хронологию уведомление машиниста
- [ ] Повторное решение по тому же поезду со второго экрана отклоняется без ошибки
- [ ] Отказ С3: штатные задачи по 101 и 2001 заменяются задачами сбоя, полный сценарий сбоя проходит как раньше
- [ ] «Сброс» возвращает штатные задачи приёма
- [ ] Миграция с RLS лежит в `supabase/migrations/`, применена в проект
- [ ] lint, typecheck, build — зелёные

## Как проверить

1. `npm run lint`, `npm run typecheck`, `npm run build`.
2. `npm run dev`, войти как ДСП, открыть пульт станции `almaty-1`:
   - у 101 (пассажирский, 14:12–14:20) открыть «Другой путь» → путь 1
     доступен (платформа, маршрут Н-1, свободен до 3412 в 14:35); пути 2, 4,
     5 — без платформы, путь 6 — тупик; выбрать путь 1 → нитка на плане,
     уведомление машиниста в хронологии;
   - 2001 (грузовой, 14:18–14:40) → путь 4 занят 2114 до 14:45, путь 1 —
     конфликт с 3412; «Принять по плану» на путь 5 → задача выполнена.
3. Во второй вкладке (ДСЦС) увидеть те же решения после опроса (3 с).
4. «Датчик: отказ С3» → задачи по 101/2001 сменились задачами сбоя;
   пройти сценарий до «Инцидент закрыт».
5. «Сброс» → штатные задачи вернулись.
