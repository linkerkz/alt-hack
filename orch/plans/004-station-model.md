# 004 — Доменная модель станции в БД

Статус: review

## Цель

Сейчас инцидент, влияние и варианты — тексты в `mock.ts`, привязанные к шагу
сценария. Нужна модель станции в Supabase, над которой система сможет сама
создать инцидент и посчитать влияние: какие поезда, маршруты и ресурсы
затронуты неисправным объектом.

## Направление

- Миграция с таблицами: станции, пути, стрелки, маршруты (через какие стрелки
  проходят), поезда, план занятости путей, ресурсы, инциденты, хронология.
- Доступность объекта не хранится флагом: объект недоступен, пока по нему
  открыт инцидент. Один источник правды.
- Статусы и виды — enum'ы, как `app_role`. Статусы инцидента — по
  `docs/case_solution.md` §7.
- RLS на всех таблицах: вошедший пользователь читает. Запись — в следующих
  шагах (вебхук IoT, Server Actions), политики добавятся вместе с ними.
- Сид — станция Алматы-1 по §4 решения: один парк, две горловины, пути 1–6,
  8 стрелок, 8 поездов на часе 14:00–15:00 в штатном режиме, без инцидентов.
- Время плана — `time` (часы демо-дня), время событий — `timestamptz`.

## Вне рамок

Код чтения в `features/*/queries.ts` и перевод пульта с моков — появятся
вместе с первым потребителем (вебхук IoT, расчёт влияния). Светофоры и
рельсовые цепи — пока только геометрия на схеме. Генерация TS-типов.

- [x] На всех новых таблицах включён RLS
- [x] Запросом по модели находятся поезда, затронутые отказом С3 (101 и 2001)
